# ai-workflow — principles

## P1. 用户陈述的事实即为真，不要重新验证

用户说「面板是空的」「颜色不对」，那就是数据。把力气花在解释和修复上，不要为了说服自己
而重现一遍。重跑用户已经做过的检查既浪费一轮，也读起来像没在听。

推论：**我自己**的主张享受相反待遇 —— 说成事实之前必须有证据（测量值、运行输出、截图）。

## P2. 讨论不是指令；任务指令不是提交授权

- 提问（「为什么不能…」「你能不能…」）要的是分析。给选项 + 建议，**不要开始编辑**。
- 工作指令（「修复 / 调整 / 更新 / 看下」）授权的是**工作本身**。代码写完，停下，问。
- 只有明确的「提交 / commit / 推送 / push」授权 git 写操作，且**只覆盖那一次提交**。

**关键判定**：修复指令 ≠ 提交指令。修复完成后正确收尾 = 报告修复内容 + 验证结果 +
「待授权提交」，然后**停**。

*事故记录*：`2026-09-07` ctt-web 的 TODO 配色修复，凭一句「你看下解决下」被自动提交并推送
到 develop **和** master。此后 R6 加了字面搜索的机械判定法。
*事故记录*：`2026-09-13` ctt-server 上，「提交并推送，然后继续实施下一阶段」被解读为后续
所有批次都已授权，AI 自行完成 12 个 develop 提交 + 9 个 master cherry-pick。
**前瞻动词不携带提交授权**——授权在指名变更提交完毕的瞬间闭合。

## P3. 验证力度匹配变更性质

| 变更 | 需要的证据 |
|---|---|
| UI / 命令行为 | 扩展实际**运行**后的观察（命令面板执行、状态栏渲染、输出通道内容） |
| 宿主 API 交互 | 真机 Extension Development Host 中的实际表现，不是类型通过 |
| 数据语义 | 真实输入下的实际输出（落盘内容、聚合结果），不是「应该对」 |
| 纯逻辑 | 覆盖该逻辑的**那个**测试/命令，输出贴出来 |
| 配置 / 边界 | 实际取值（配置读取、默认值生效）的观测 |

测试是**长期资产**，不是工作量的证明：一个测试只有在「合理 bug 会让它失败」时才值得存在。
行为、边界、不变量值得测；连线、默认值、源码文本不值得。

**VS Code 特有**：类型检查通过 ≠ 扩展能工作。宿主 API 的失败模式（未释放的 Disposable、
事件未触发、权限/激活时机）在 `tsc` 中完全不可见。

## P4. 时间线层不是知识的存储

`activeContext.md` / `progress.md` 回答「最近改了什么」。可复用的知识 —— 不变量、决策树、
取值范围、坑 —— 属于领域层，否则下次归档时间线时它就被埋了。

*证据*：ctt-web 的 `activeContext.md` 曾涨到 549 行，因为每一轮都在**追加**而不是**分类**。
修复方式不是编辑它，而是把持久部分移进领域文件、其余归档。

## P5. 知识只以最终形态书写

一个知识文件要么**现在为真**，要么**事实上是错的** —— 不存在「草稿」状态：

- 不要占位符、不要 `TODO: fill`、不要空章节。写不出真话，说明知识尚不存在，**就不要建这个文件**。
- 不要 changelog 口吻（「v0.34.0 把 X 改成了 Y」）。记录**当前真相**加上让它稳定的理由；
  版本历史属于 `progress.md` 与 git log。
- 不要重复：横切约定留 `systemPatterns.md`，领域判断留领域文件。两份副本必然漂移，
  正确答案是**链接**而不是第二份拷贝。

## P6. 一个事实一个归属

每个事实恰好有一个权威文件，其余地方一律链接。
一条重复的规则会变成两条分歧的规则；一个重复的事实会变成某个人记忆里的过期标签。

**冲突时的裁决顺序**：源码 > 领域文件 > 时间线层 > 我的记忆。
本仓库针对 ctt-server 契约的推论尤其如此 —— 文档措辞与源码不一致时，**源码赢**
（已记录 8 处此类不一致，见 `../server-api/references.md`）。

## P7. 先分类再动手

每个到来的东西必属其一：**需求**（要做）、**问题**（要分析）、**报告**（要诊断）、
**规则变更**（要改规则本身）。分类决定整个回应的形状 ——
把提问误判为指令是最常见也最昂贵的错误（P2）。

## P8. 边界是硬的，不是偏好

只读就是只读：关联仓库**永不编辑**，哪怕明知那里有错 —— 改为向用户提交需求文本（R3）。
资源只在自己启动时才拆除；归属按**实际监听进程**验证，不按记忆中的 PID。

本仓库是 CTT 体系里的**第三个客户端**，越权改动造成的污染会横跨三个仓库。

## P9. 工作区保持干净可复现

临时产物（探针脚本、测试账号、验证用服务）任务结束时删除；持久助手（测试账号、脚本）复用而非重建。
脏工作区会让下一次验证不可靠。

**只关自己启动的服务**。VS Code 的 Extension Development Host、watch 进程、
`vscode-test` 下载的宿主实例都算资源，用完必须停。

## P10. 陈旧知识比没有知识更危险

一个自信的、错误的记忆比空白更有害，因为它会被当作事实使用。

本仓库的直接证据：`../code-time-tracker` 的 `memory-bank` 有五处陈述（版本号 0.8.10、
「云同步未实现」等）与其自己的源码矛盾，因为 R2 只要求**写**记忆，没有任何规则要求
**核对**记忆与代码。规则在写、事实在漂，两者会各自走远。

因此：**动手前若记忆与代码冲突，先怀疑记忆**；确认是代码变了就**就地改记忆**，
不要「恢复旧版本」（R10 变更溯源）。

# server-api — scenarios

> 来源：`../ctt-server` 源码 + `ErrorCode.java` 注册表 + `application.yaml`
> 最后确认：2026-09-15 ｜ 适用范围：调用服务端时的触发→判断→动作 ｜ 状态：**已核实**

触发 → 判断 → 动作。

## 接入一个新端点

| 触发 | 判断 | 动作 |
|---|---|---|
| 要用某个 `/api/v1/...` | 文档与源码可能不一致 | **读源码**（Controller + DTO 记录）确认路径、方法、参数名、字段名与类型；再写代码 |
| 需要一个新字段 | 服务端是否已返回？ | 先读响应 DTO 源码；没有则走「需要服务端改动」流程 |
| 响应里有可空字段 | `non_null` 让它**缺失** | 类型标 `optional` + 给默认值；不要判 `=== null`（P3） |

## 消费统计数字

| 触发 | 判断 | 动作 |
|---|---|---|
| 显示总览 / 热力图 / 连续天数 / 时段分布 | 这是 **merge** 语义 | 各桶之和应等于 `summary.total`；不等说明参数或口径有误，去查 |
| 显示语言 / 项目 / 星期 / 设备 / IDE 分布 | 这是 **accumulate** 语义 | 各项之和**可以**超过总览；**不要按 merge 口径合并时长**，**不要**当 bug 修。<br>⚠️ 本行说的是**时长语义**——与 P10 的**语言名归一化**无关（那件事服务端已经在做，见 P10） |
| 显示 hourly / week-hour | 这是**日均值** | 不与 `summary.total` 比较 |
| 用户说「数字不对」 | 先分清是哪种错 | 见下方「数字对不上」 |
| 需要某个年份/月份列表 | 服务端有专门端点 | 用 `heatmap-years` / `heatmap-months`，**不要**拉全量热力图自己推 |

## 「数字对不上」

依次排查：

1. **时区**：是否发送了 `timezoneOffset`？（默认 0 = UTC，会与用户本地直觉不符）
2. **语义**：比较的两组数是否同属一种语义？（merge 与 accumulate 不可比）
3. **维度**：`hourly`/`week-hour` 是均值，`summary` 是总和
4. **设备/IDE 过滤**：是否传了 `deviceId` 或 `ideName`？两者**同时传会被拒**（`400 COMMON_003`）
5. **权威性**：与 JetBrains 插件或 ctt-web 对比时，三方读的是同一批服务端语义；
   若真有分歧，**服务端正确**（P7）

## 出错响应

| 触发 | 判断 | 动作 |
|---|---|---|
| 解析错误码得到 `undefined` | 可能落在过滤器路径 | 同时读 `$.code` 与 `$.data.code`（P2） |
| `401 AUTH_010 / AUTH_011` | 凭据无效 / 过期 | 终态：提示用户重新配置 API Key，**不要重试** |
| `403 AUTH_012 / AUTH_020` | 被吊销 / 缺 scope | 终态：提示重建 Key（需含所需 scope） |
| `404 COMMON_002` | **不区分**「不存在」与「不属于你」 | 不要试图区分；对设备类调用先注册再重试 |
| `400 COMMON_003` | 校验失败 | 修请求，不要盲目重试；`details[]` 里有 `{field,message}` |
| `429 RATE_LIMIT_001` | 被限流 | 按 P6 退避：`Retry-After` 头 → `retryAfter` 体 → 稍后 |
| `500 SYSTEM_001` | 未处理异常 | 退避重试，报错时带上 `traceId` |
| `AUTH_021` | —— | **永远不会出现**，源码中从未抛出；不要为它写分支 |

## 需要服务端改动

1. **不自行修改** `../ctt-server`（AGENTS.md R3）
2. 写需求报告到 `.omp/<topic>-requirement.md`，五段齐全：
   **现状 / 期望行为 / 理由 / 影响面 / 验收标准**
3. 报告交用户，由用户联系服务端负责人
4. 期间让本仓库对限制**诚实**（注释 / README / UI 提示），而不是伪造或悄悄不一致

## 认证方式选择

| 场景 | 用什么 |
|---|---|
| 扩展日常调用（拉取、推送、统计） | **API Key**（`cttak_...`），存 `context.secrets` |
| 用户首次绑定 / 创建 Key | 一次性 JWT 登录（或引导用户在 ctt-web 创建后粘贴） |
| 需要知道当前账号 | `GET /api/v1/users/me`（JWT 或带 READ 的 Key） |

**判断依据**：桌面/IDE 客户端用 Key —— 无需刷新令牌、无浏览器跳转、可长期有效。
JWT 只用于「铸造 Key」这一次动作。详见 `../sync-client/practices.md`。

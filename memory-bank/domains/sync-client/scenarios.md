# sync-client — scenarios

> 最后确认：2026-09-15 ｜ 适用范围：同步问题的诊断路径 ｜ 状态：**已核实**

触发 → 判断 → 动作。

## 实现 / 修改同步主流程

| 触发 | 判断 | 动作 |
|---|---|---|
| 首次实现同步 | 三步循环，顺序有意义 | pull（拉服务端权威）→ push（推本地 dirty）→ pull（收敛）；见 `practices.md` |
| 要改 push 的批量大小 | 服务端无上限，客户端自律 | 保持分批（参考实现 500）；不要一次推全部 |
| 要给 push 加副作用 | 服务端副作用是**失败容忍**的 | 客户端同理：本地落盘失败不应回滚已确认的推送 |
| 要加新的同步触发时机（定时/手动/关窗） | 关窗时**不能等网络** | 落盘本地状态后立即返回；网络部分放后台 |

## 诊断同步报告

| 触发 | 判断 | 动作 |
|---|---|---|
| 「新设备一次拉了全部数据」 | 无界响应正是分页要解决的 | 检查是否循环消费 `hasMore`；确认 `pull-batch-size` 生效 |
| 「某设备少了一个会话」 | 区分「数据不存在」与「跳过了一页」 | 比较该设备游标与服务端 watermark；watermark 领先 = 页面生成但未被应用（P8） |
| 「同一个会话出现两次」 | 内容级去重应当收敛 | 检查 `sessionUuid` 唯一性与「重推是否携带了完全相同的业务内容」 |
| 「设备重装后不再同步」 | 吊销或设备未知 | 两者都返回 `404 COMMON_002`；重注册**同一** `deviceId` 即可 |
| 「在 B 编辑后，会话从 A 的统计里消失」 | origin 与 last-writer 混淆 | 统计必须过滤 `origin_device_id`；过滤了 writer 就是缺陷（P6） |
| 「push 一直失败但服务端有数据」 | 检查是否整批回滚 | push 是原子的；部分可见 = 服务端缺陷，走需求报告 |

## 处理失败

| 触发 | 判断 | 动作 |
|---|---|---|
| pull 失败 | 游标不能动 | 保持原游标，下轮重试 |
| push 失败 | dirty 必须保留 | 不清标记；下轮重试整批 |
| `429` | 双信号退避（`../server-api` P6） | `Retry-After` 头 → `retryAfter` 体 → 稍后；不发 4xx 重试风暴 |
| `404 COMMON_002` | 设备未知/他人/已吊销 | 重新注册同一 `deviceId`，然后重试 |
| `401/403` 认证类 | 终态 | 停止同步，提示用户重新配置 Key（**不要**循环重试） |
| `5xx` / 网络错误 | 可重试 | 记日志，下轮重试；连续失败要能让用户看到状态 |
| 时间戳解析失败 | 不能污染 LWW 排序 | 覆盖时保留原值；新建时才用当前时间。**绝不**写入最小值（会毒化排序） |

## 账号切换

| 触发 | 判断 | 动作 |
|---|---|---|
| 用户解绑 / 换 Key / 换账号 | 旧游标对新账号无意义 | **清空**游标（或按账号隔离存储）；本地数据归属需明确（见下） |
| 换账号后统计只显示一个账号的数据 | 参考实现是**按账号隔离**，不混算 | 明确本仓库策略后写进 `principles.md`；不要静默混算 |

## 本地删除是否参与同步

参考实现**明确取消**了本地删除的同步（决策 B3），`is_deleted` 实际恒为 0。
本仓库需同样明确表态 —— 不表态会导致「本地删了但云端还在，下次 pull 又回来」的困惑。

服务端支持 `deleted=true` 的软删除（`chk` 约束与 `op=DELETE` 均在），
所以这是**产品决策**而非能力限制。
